# 1. 과제 개요

## □ 추진배경
※ 기술동향 등 군내외 환경분석

ㅇ **군내 환경 — 정비 데이터 관리의 구조적 한계**
- 군수통합정보체계(DELIIS)가 정비이력 **단순 축적 위주**로 운영되어 데이터 연계성·통합성 부족
- 데이터 예측·분석 기능 미흡 → 추출 후 **엑셀 수기 분석**에 병력 소요 (보고서 1건당 평균 **45분**)
- 운용자 숙련도에 따라 분석 내용 상이, **실시간 정보 제공 제한**
- 조종사 Write-up(비정형) ↔ 기술도서 결함코드(정형) 간 **해석 간극** → 오진율 숙련도별 **15~40% 편차**
- CAD/PAD 시한품목이 엑셀 파편화 관리 → 교체 시기 누락·조기교체 등 **안전·자원 리스크**

ㅇ **군내 환경 — 국방 보안 제약**
- **국방 폐쇄망(망분리)** 특성상 민간 범용 AI(클라우드 LLM) **직접 연동 불가**
- 정비 현장 데이터의 외부 유출 방지를 위한 **온프레미스 AI** 구축 필요

ㅇ **군외 기술동향 — MRO·항공 정비 AI**
- 민간 항공 MRO 분야 **예측정비(CBM)·디지털 트윈** 도입 가속 (Lufthansa AVIATAR, Boeing AnalytX 등)
- **Document AI**(LayoutLM)·**RAG(검색증강생성)** 기술 성숙 → 비정형 문서·매뉴얼 자동 해석 가능
- **소형 언어모델(sLLM)** 온프레미스 구동 기술 확산 → 폐쇄망 환경 생성형 AI 적용 가능성 확대

ㅇ **군외 기술동향 — 국방 AI 정책**
- 국방 AI 추진 전략에 따른 **병력운영 효율화·데이터 기반 의사결정** 강조
- 공군 **피지컬 AI·정비·관제 혁신** 방향과 본 과제(군수① 정비 자동화) 정합

※ 최종목표 및 연구개발 분야별 주요목표

ㅇ **최종목표** ※ 정성적 목표

- **국방 폐쇄망 환경에 최적화된 AI 기반 항공기 정비관리 자율화·자동화 체계 구축**

- DELIIS 연계형 **정비 데이터 수집·정형화·분석·예측 일원화** 플랫폼 실현
- 비행단 내 **소모성 정비 부품·군수 행정** 범위에 집중하여 **단기 실증·시범 도입 가능한** 실용 체계 확보

ㅇ **연구개발 목표** ※ 정량적 목표

| 결함 오진율 | 기존 대비 **30% 감소** |

| OCR 인식률 | 군수 지정 서식 기준 **95% 이상** |

## □ 기대효과

ㅇ **병력절감·업무 효율 (유형)**
- 정비 행정·분석 병력 **30% 이상** 절감, 보고서 작성 시간 **60% 단축**
- 엑셀 수기 분석·DELIIS 수동 입력 업무 대폭 축소

ㅇ **정비 품질·안전 (무형)**
- AI 표준 가이드로 결함 오진 감소, CAD/PAD 선제 알람으로 **안전 리스크 사전 차단**
- RAM(신뢰도·가용도·정비도) 실시간 관리 → 기체 **가동률 향상**

ㅇ **지식·조직 역량 (무형)**
- 정비 Wiki로 고참 현장 노하우 **디지털 보존** → 전출 시 지식 공백 최소화
- 데이터 기반 정비 의사결정 문화 정착

ㅇ **경제성**
- 부품 조기·지연 교체 낭비비용 절감, 오진에 따른 불필요 정비 공수 절감
- 민간 클라우드 AI 미사용 → **라이선스·망연계 비용 절감**

# 2. 과제 구축 내용

## □ 단계별 목표
※ 기획/설계단계, 개발/실증단계로 분리

ㅇ **기획/설계단계 (0~3개월, PoC)**

- 현장 요구사항 분석 및 Pain Point 검증 (정비사·군수 행정 인터뷰)
- DELIIS 스키마 호환 데이터 모델·API 설계
- 3 Pillar 기능 명세 및 AI 모델 선정 (LayoutLM, sLLM, RAG, LSTM)
- 폐쇄망 아키텍처·보안 설계 (온프레미스 GPU 서버, AES-256, 감사 로그)
- **웹 PoC 개발·시연** (Write-up·OCR·시한품목·Wiki) — ✅ 완료

ㅇ **개발/실증단계 (3~12개월, 시범)**

- 온프레미스 AI 서버 구축 및 sLLM·RAG 파이프라인 실연동
- LayoutLM OCR 군수 서식 Few-shot 학습 및 DELIIS 모의 DB 연동
- 1개 비행단 파일럿 운용 및 KPI 측정 (보고서 시간, 오진율, 시한품목 누락)
- Human-in-the-loop 확인 UI 고도화, 정비 Wiki QR/NFC 연동

ㅇ **확산단계 (12개월+, 전단)**

- DELIIS 실연동, 동적 정비 스케줄링(OR+강화학습) 도입
- 타 비행단 확산 및 운영 매뉴얼 표준화

## □ 개발/구축내용
※ 개발/구축대상 범위 및 주요내용 기술

ㅇ **국방 폐쇄망 최적화 AI 기반 정비관리 체계(MAINT-AI Lite) 구축**

- 비행단 내 **소모성 정비 부품(CAD/PAD) 및 군수 행정 프로세스** 대상 지능형 정비 플랫폼
- **완전 폐쇄망(온프레미스)** — 부대 내 AI 서버·중계 서버·태블릿/웹 단말 설치·운영
- DELIIS 스키마 호환 설계로 정비 데이터 **수집·정형화·분석·예측** 일원화

ㅇ **Pillar 1 — 수기 정비자료 AI 데이터화 및 DELIIS 자동 매핑**

- 태블릿 카메라 → **OCR·LayoutLM v3** → DELIIS 정형 데이터 자동 변환
- Diffusion 화질 복원, Human-in-the-loop 확인 UI

ㅇ **Pillar 2 — 조종사 Write-up AI 해석 및 정비 가이드 자동 생성**

- **로컬 sLLM + RAG** → 결함코드·TO 페이지·체크리스트·TAT 자동 생성
- 기술도서(PDF)·과거 결함 이력 Vector DB 통합

ㅇ **Pillar 3 — 시한품목(CAD/PAD) 수명 주기 예측 및 선제 알람**

- LSTM/Transformer 예측, D-Day 알림, RAM 대시보드

ㅇ **부가 — 정비 Wiki (QR/NFC 장비 태그)**

- 장비별 현장 노하우 기록·공유·계승

## □ 개발기술 특징

ㅇ **개발기술 핵심 요소** ※ 중점 기술개발분야

- **폐쇄망 로컬 sLLM + RAG** — 국방 보안 환경 생성형 AI 정비 보조
- **LayoutLM v3 Document AI** — 군수 특화 서식·약어·필체 OCR
- **Write-up → 결함코드 의미 매핑** — 비정형·정형 데이터 브릿지
- **시계열 예측(LSTM/Transformer)** — CAD/PAD Shelf Life 선제 알람
- **QR/NFC 연동 Wiki** — 현장 tacit knowledge 디지털화

ㅇ **기술특징** ※ 기술 특장점

- **폐쇄망 end-to-end**: OCR → DELIIS → RAG 추론까지 온프레미스 일원화 (민간 클라우드 AI 불필요)
- **좁고 깊은 스코프**: 항공기 전체 MRO가 아닌 소모품·행정 집중 → **6개월 PoC 실증 완료**
- **Human-in-the-loop**: AI 결과 정비사 최종 확인 → 군수 현장 신뢰도 확보
- **DELIIS 상위 보조 레이어**: 기존 체계와 중복 없이 **입력·분석·예측 자동화** 추가
- **웹 PoC URL 제공**: https://dhalsdyd.github.io/maint-ai-hackathon/

## □ 체계구축/운영

ㅇ **구축개념** ※ 통합연동 및 운영개념 포함

- **3계층 아키텍처**
  - [단말] 태블릿/웹 앱 — 정비사·관리자 UI (Write-up, OCR, 알람, Wiki)
  - [AI] 온프레미스 GPU 서버 — OCR / RAG+sLLM / 예측 엔진
  - [데이터] DELIIS 연계 DB · 기술도서 · 결함이력 · 시한품목 DB
- **DELIIS 통합연동**: 스키마 호환 JSON API, PoC(모의 DB) → 시범(실연동) 단계적 연계
- **망분리 준수**: 모든 AI 추론·데이터 처리 폐쇄망 내부 완결

※ 삽입 이미지: `docs/assets/maint-ai-architecture.png`

ㅇ **운영개념** ※ 개별, 통합운영개념

- **개별 운영**: 정비사가 현장에서 Write-up 입력·OCR 촬영·Wiki 조회 — 단말 독립 사용 가능
- **통합 운영**: AI 서버가 OCR·RAG·예측을 중앙 처리, DELIIS·RAM 대시보드 실시간 연동
- **Human-in-the-loop**: AI 추론 결과 → 정비사 확인 → DELIIS 반영 (오탐 방지)
- **단계적 도입**: PoC → 1개 비행단 시범 → 전단 확산
- **보안 운영**: 감사 로그, AES-256, 외부 API 차단, 모델·DB 온프레미스 상주

## □ 추진전략
※ 개발과제 각 단계별 추진전략

|------|------|----------|
| PoC | 0~3개월 | 웹 PoC 완성 → 예선 심사 · 핵심 기능 4종 시연 |

ㅇ **세부전략**

- **PoC 단계**: Write-up RAG를 **데모 메인**으로 집중 시연, OCR·시한품목·Wiki 보조 실증
- **시범 단계**: 군수 현장 인터뷰 기반 LayoutLM Few-shot 학습, DELIIS 담당자 협의 실연동

- **팀 역량 분담**: PM(기획·KPI) / 도메인(As-Is 검증) / 개발(웹·앱) / AI(RAG·OCR)

## □ 제한사항
※ 추진과정 중 예측되는 제한요소 및 해결방안

ㅇ **DELIIS 실연동 제약**
- 제한: PoC 단계 DELIIS 직접 연동 어려움
- 해결: **스키마 호환 모의 DB** 구축·데모, 시범 단계 실연동 로드맵 명시

ㅇ **폐쇄망 AI 자원**
- 제한: GPU 서버·sLLM 구축 비용·전력
- 해결: **경량 sLLM(7B)** 우선 도입, 단계적 GPU 확장

ㅇ **OCR 오인식**
- 제한: 현장 오염·필체 문서 인식률 저하
- 해결: Diffusion 전처리 + **Human-in-the-loop** 확인 UI

ㅇ **기존 수상작·기적용 중복**
- 제한: 심사 시 중복 탈락 가능
- 해결: Write-up 매핑 + 시한품목 + DELIIS **3요소 조합** 차별화

ㅇ **정비 현장 데이터 확보**
- 제한: 실제 군 정비 데이터·TO 문서 접근 제한
- 해결: **합성·공개 시나리오** PoC, 시범 단계 현장 데이터 연계

- 공군 5대 임무 중 **작전지원(군수)** 분야 병력운영 효율화 실현
- **군수②(피지컬 AI)** 연계: 현장 AR·햅틱·로봇 정비 보조로 로드맵 확장

ㅇ **군내 확대 — 타 군·부대**
