# MAINT-AI Lite — 아이디어 기획서

**지정공모 (군수①) AI 기반 항공기 정비관리업무 자율화·자동화 체계 구축**

---

## §1. 배경 및 필요성 (As-Is)

### 1-1. 공군 정비관리 현황

- **군수통합정보체계(DELIIS)** 가 정비이력 단순 축적 위주 → 데이터 연계성·통합성 부족
- 데이터 예측·분석 기능 미흡 → **엑셀 수기 분석**에 병력 소요
- 운용자 숙련도에 따라 분석 내용 상이 → **실시간 정보 제공 제한**
- **국방 폐쇄망** 특성상 민간 범용 AI 직접 연동 불가

### 1-2. 현장 Pain Point (정량)

| # | 현상 | 근본 원인 | 정량 지표 |
|---|------|----------|----------|
| 1 | CAD/PAD 교체 시기 누락 | 엑셀 파편화 | 월 평균 3~5건 누락 추정 |
| 2 | Write-up 해석 오류 | 비정형↔정형 간극 | 오진율 숙련도별 15~40% 편차 |
| 3 | 수기 정비기록 입력 | DELIIS 미연동 | 보고서 1건당 45분 소요 |
| 4 | 고참 노하우 증발 | 지식 아카이브 부재 | 전출 시 70%+ 노하우 소실 |

## §2. 제안 개요

**플랫폼명:** MAINT-AI Lite  
**타깃 사용자:** 정비사, 정비 관리자, 군수 행정 담당  
**한 줄 가치:** 폐쇄망에서 수기·엑셀 정비 업무를 AI로 자동화하여 인력 낭비와 분석 오류를 동시에 해결

### As-Is / To-Be

```
[As-Is]
조종사 Write-up(텍스트) → 정비사 경험 의존 해석 → 수기 정비기록 → 엑셀 분석 → DELIIS 수동 입력

[To-Be]
조종사 Write-up → [RAG Copilot] → 정비 가이드·체크리스트 자동 생성
수기 정비기록지 → [OCR+LayoutLM] → DELIIS 자동 매핑
CAD/PAD 이력 → [예측 알람] → 선제 교체 알림 + RAM 대시보드
```

## §3. 핵심 기능 (3 Pillar × 3단계 프레임)

### Pillar 1 — 수기 자료 데이터화 (OCR + DELIIS 서식 맵퍼)

#### 현상의 원인 분석
- 정비 현장 거친 환경 → 수기 기록지 오염, 필체 차이, 국방 약어(A/C, FH 등)
- 범용 OCR 인식률 급락 → DELIIS 스키마와 연동 불가 병목

#### AI 기반 메커니즘
- **전처리:** Diffusion 기반 화질 복원 (흐린 필체·오염 영역 보정)
- **인식:** LayoutLM v3 Few-shot 파인튜닝 → 문맥 기반 필드 매핑
- **출력:** DELIIS 호환 JSON 스키마 자동 생성

#### 단기 실증 전략
- Flutter 태블릿 카메라 촬영 → Grid View 격자 매핑 → DELIIS 서식 자동 입력 UI

---

### Pillar 2 — Write-up 해석·정비 가이드 (RAG Copilot) ★ 데모 메인

#### 현상의 원인 분석
- 조종사: "HUD 타겟팅 기호 간헐적 흔들림" (비정형, 주관적)
- 정비사: 기술도서 결함코드 (정형, 전문적) → **해석 간극**으로 엉뚱한 부품 점검

#### AI 기반 메커니즘
- 기술도서(PDF) + 과거 결함 이력 → **Vector DB** 임베딩
- **로컬 sLLM** (Llama 3 / Qwen 2) + **RAG** → 유사 사례·권장 수리방안 추론
- 출력: 관련 TO 페이지, 체크리스트 5항목, 예상 TAT, 결함코드 매핑

#### 단기 실증 전략
- Flutter: 증상 입력 → 1초 내 AI 응답 (대화형 UI)
- 시연 시나리오: F-15K + "HUD 타겟팅 기호 간헐적 흔들림" → 가이드 생성
- (선택) 햅틱 모드: 현장 작업 중 Eyes-free 진동 알림

---

### Pillar 3 — 시한품목(CAD/PAD) 수명 주기 관리

#### 현상의 원인 분석
- 사출좌석, 채프/플레어, 미사일 신관 등 **Shelf Life** 엄격
- 기체별 장착 이력이 엑셀 여러 파일에 파편화 → 교체 시기 선제 알람 불가

#### AI 기반 메커니즘
- 기체 장착 이력 + 부품별 Shelf Life → **LSTM/Transformer** 시계열 예측
- **선제 알람:** D-Day 7일/3일/당일 푸시
- **RAM 대시보드:** 신뢰도·가용도·정비도 지표 시각화

#### 단기 실증 전략
- Flutter: "이번 주 교체 대상" 대시보드 + 알람 카드 UI

## §4. 차별화·창의성

- **Write-up → 결함코드 표준화:** 단순 챗봇이 아닌 정비 워크플로우 단계별 자동화
- **폐쇄망 end-to-end:** OCR → DELIIS 매핑 → RAG 추론까지 온프레미스
- **좁은 스코프:** 소모품·행정으로 실현가능성 극대화
- **현장 Wiki:** NFC/QR 스캔 → 고참 노하우 위키 (창의성 보강)
- **햅틱 어시스턴트:** 시선·양손 점유 현장에서 Eyes-free 작업 지원

## §6. 실현 계획 (3단계 로드맵)

| 단계 | 기간 | 마일스톤 |
|------|------|---------|
| **1. PoC** | 0~3개월 | Write-up RAG + OCR UI + 시한품목 대시보드 (Flutter) |
| **2. 시범** | 3~12개월 | DELIIS 스키마 연동, 1개 비행단 파일럿 |
| **3. 확산** | 12개월+ | 동적 스케줄링(OR+RL), 현장 Wiki, 햅틱·AR(군수② 연계) |

### 로드맵 2단계 — 동적 정비 스케줄링 (PoC 이후)

- **원인:** 돌발 결함·비행일정 변경 시 자격급수·정비고·재고 3대 제약 실시간 반영 한계
- **AI:** PPO/DQN + 유전 알고리즘 → Gantt 자동 재배정
- **실증:** 슬라이더 변수 조절 → 간트차트 실시간 최적화 시뮬레이션
